# Glass Messenger — standalone Windows demo

Windows demo built with **Electron + React + TypeScript + Vite + Tailwind CSS v4 + Zustand + Motion**. This is a fictional offline design prototype, not a Zalo client.

Observed verification: full TypeScript + ESLint checks, **89/89 Node tests**, **26/26 browser E2E scenarios**, development launch, packaged Electron smoke, a **150-send** stability soak (run twice — no accumulation, though natural reclamation latency varied between runs), a portable-wrapper smoke and an extended desktop check (drag-region hit map, DPI/zoom, accessibility tree, full-window shell geometry) pass on Windows. Both npm audits report zero advisories. Exact versions are locked. See [delivery evidence](reports/AGENT_DELIVERY.md) for the final portable artifact, hash, command logs and remaining manual checks, and [R10](reports/R10_MOCK_DESKTOP_CLIENT.md) for the mock-workflow status. Everything here is `MOCK_PASS`; nothing has been connected to a real Zalo backend.

## Run on Windows

Use Node.js 24 LTS and npm from the project directory:

```powershell
npm ci
npm run dev
npm run dev:desktop
```

The lockfile was generated by a successful install. Use `npm ci` for subsequent clean/CI installs. Electron 45 downloads its Windows runtime on first use, and electron-builder may download packaging tools. The application itself is offline. The unused Squirrel helper may emit an npm install-script warning; this project builds the portable target and does not need Squirrel installation.

`npm run dev` opens a Vite server at `http://127.0.0.1:5173`; open that address in your browser. `npm run dev:desktop` compiles main/preload, starts its own Vite server and opens the demo Electron window. Close the window or use Ctrl+C to stop its server. Do not run both commands on the same port.

## Verify and package

```powershell
npm test
npm run check
npm run build
npx playwright install chromium
npm run capture:legacy
npm run test:e2e
npm run build:electron
npm run test:desktop
npm run test:desktop:extra
npm run test:soak
npm run build:desktop
```

- `npm test`: 89 tests — the seven original helper tests, then adapter/preferences/security, history, transfer, call, network, design-system and layer-boundary guards, plus the services, loopback-transport and composition suites. Node's in-process test runner avoids the observed worker-spawn restriction.
- `npm run check`: full TypeScript checks, ESLint, tests. Syntax-only checks do not replace this gate.
- `npm run test:e2e`: builds and serves the production renderer, exercises critical components, checks axe and sampled text contrast, and writes dark/light screenshots at 1920×1080, 1600×900 and 1366×768.
- `npm run test:desktop`: requires built renderer/main/preload; tests two launches, local send, runtime sandbox/bridge, titlebar controls and captures Electron screenshots.
- `npm run test:desktop:extra`: requires built renderer/main/preload; verifies the titlebar drag region and that every window button is `no-drag` and clickable, layout at 1000×700/1366×768/1920×1080, device scale factors and browser zoom from 1 to 2, that the desktop shell fills the window with no gutter/rounding/rim (padding 0, rect = viewport, radius 0, no shadow, no scroll, all four corners inside the shell), that the accessibility tree exposes no unnamed interactive node, and that the window controls are keyboard focusable. Writes `reports/desktop-extra-qa.json`.
- `npm run test:soak`: requires `release/win-unpacked`; sends 150 local messages across 30 settings cycles (override with `SOAK_BATCHES`), reloads twice, checks live DOM returns to baseline, measures how long the engine takes to reclaim detached documents without forcing GC, then closes cleanly. Writes samples to `reports/stability-smoke.json`.
- `npm run build:icon`: regenerates `build/icon.ico` (seven sizes) from `tools/make-icon.cjs`; no binary blob to edit by hand.
- `npm run verify:asar`: compares every bundled program file (`dist/**`, `dist-electron/**`) byte-for-byte against the packaged `release/win-unpacked/resources/app.asar` and writes `reports/asar-parity.json`. `build:desktop` runs it automatically after packaging.
- `npm run build:desktop`: Windows x64 **portable executable** at `release/Glass-Messenger-Demo-<version>-x64.exe` (currently `0.3.0`). The hash helper records every built artifact in `reports/desktop-artifacts.json` and flags the current version as the delivery artifact.
- After the build has fully finished, test the unpacked app with `npm run test:desktop -- "release/win-unpacked/Glass Messenger Demo.exe" unpacked` and the portable wrapper with `node tools/smoke-portable.cjs`. The latter uses a temporary loopback CDP port because NSIS does not forward Electron inspector output. Do not build while the soak is running: the unpacked app holds its executables open.
- `npm run dev:desktop -- --smoke`: exercises the same Vite/dev renderer setup, sends a demo message and closes the application/server automatically.
- No installer is run automatically. The prototype is unsigned and ships the generated demo icon from `build/icon.ico`.

The optional `tools/check-source.cjs` checks syntax using TypeScript; it explicitly does not validate dependency types.

## Demo behavior

Search names/previews without Vietnamese accents; filter unread/group/work conversations; pin or mark unread; send local sample text; add emoji or a reaction. Enter sends, Shift+Enter adds a newline, and IME composition is respected. The native settings dialog supports Escape and browser focus containment.

The file picker retains only up to ten file names and sizes per selection. It never reads file contents or uploads them; attachments show a simulated upload/download progress that can be cancelled mid-flight. Calls are mocked state machines only — no microphone, camera or network is touched. The "Phòng thử demo" menu can simulate an incoming message, a failed send and a lost connection; reconnecting flushes pending mail and leaves deliberately failed messages for the reader's own "Gửi lại". Cloud, journal and tools are visibly described as demo/placeholder actions.

Only theme, glass strength, motion and low-blur preferences persist. Messages and drafts reset on reload/restart. Reduced motion follows the OS even when UI animation is enabled. The desktop app's own cache/preferences live in `.glass-demo-data` inside the development project or next to the portable executable; run the portable app from a writable directory.

## Structure and rollback

- `src/renderer/`: React components, Zustand store, typed offline adapter and glass styles.
- `src/shared/`: pure logic and preference validation.
- `electron/`: secure BrowserWindow, local asset protocol, minimal window-control bridge.
- `tests/`: legacy tests, pure TypeScript tests, browser E2E.
- `legacy/`: complete original browser prototype with assets and original package manifest.
- `reports/`: actual command evidence; [legacy checksums](reports/legacy-sha256.txt).
- [Component map](docs/UI-COMPONENT-MAP.md), [architecture](docs/ARCHITECTURE.md), [QA](docs/QA-CHECKLIST.md), [manual QA procedures](docs/MANUAL-QA.md).

To inspect or roll back to the original working prototype, open **`legacy/index.html`**. Its original files are untouched. The migrated root `index.html` requires Vite/build output and should not be double-clicked.

## Actual Zalo

A read-only metadata sweep was run on 2026-11-05 after explicit user approval: Zalo PC 26.10.20.3253, VNG-signed, `resources\app.asar` plus Chromium packaging markers. See [recon report](reports/ZALO_ARCH_RECON.md).

A deeper read-only pass then read three bundled JavaScript files to settle the theme question: Zalo ships an internal `DARK/LIGHT/SYSTEM/CUSTOM` theme engine with CSS token palettes, but the CUSTOM dashboard is debug-menu-gated and the shipped renderer and preload expose no third-party CSS or script hook. See [feasibility report](reports/ZALO_THEME_FEASIBILITY.md).

Neither pass read or changed any Zalo profile, chat database, credential, token, media asset or network traffic, and REA was never attached to Zalo. Nothing was executed.
